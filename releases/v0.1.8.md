# Qunica v0.1.8

## Highlights

- Model agents now use Rig AgentRun by default. OpenAI-compatible Chat, Anthropic, Gemini and OpenAI Responses share one provider implementation, including auxiliary requests for titles, compaction, prompts and commit messages.
- Durable execution checkpoints preserve complete signed/opaque assistant messages, original tool batches and individual results. Approval resumes settle the original calls before requesting another model turn; tools with an unknown external outcome are not automatically replayed.
- Attempt IDs and cumulative budgets survive safe-boundary compaction and recovery. Empty successful replies retain silent-turn behavior, and interrupted or invalid streams cannot release tools. Qunica continues to own tools, approvals, MCP, skills and group scheduling.
- Added account-scoped execution metrics and an intake pause control. Historical native continuations keep their original attribution, while saved native engine settings select Rig for new work.
- Hardened approval identity checks and legacy webhook deduplication against JSON key ordering and float-parser differences. Improved SQLite retention and snapshot-cursor indexing.

## Downloads and upgrade notes

- Back up the SQLite database and workspaces, and finish or stop active tasks before upgrading. This release includes retention/index, digest-version, compaction and engine-observation migrations. Do not downgrade a migrated database.
- Recorded old approvals retain a recovery path. If a tool started but its result was not saved, inspect its external effects before deciding how to continue; an unknown Shell outcome is not safe to rerun automatically.
- Update backend and clients together. New model executions use Rig even when an older saved configuration says `native`. Review provider/gateway compatibility and recovery details in [RIG_MIGRATION.md](https://github.com/sligter/qunica/blob/v0.1.8/RIG_MIGRATION.md).
- Source builds require Rust 1.97.1. The `rig-engine` build flag remains compatible; disabling default features still includes Rig. Android remains a client and does not run the backend.
- Android 8.0 or later: choose `qunica_0.1.8_android-arm64-release.apk` for most phones, or `qunica_0.1.8_android-x86_64-release.apk` for compatible devices and emulators. Formal APKs retain the existing release signing identity.
- Windows: choose the installer or portable executable; macOS: choose the matching DMG; Linux: choose the matching package. Headless servers use the matching `qunica-server-*` archive with its SHA-256 checksum.
- Automated contracts and platform builds do not establish live acceptance for every provider/gateway or two release observation windows. Those checks remain separate from this publication.
