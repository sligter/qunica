# 工作区文件引用、编辑与预览设计

## 目标

让群聊和私聊中的右侧工作区文件面板成为可直接使用的上下文入口：用户可将文件拖到聊天输入框形成待发送附件引用，将文件夹拖入输入框形成相对路径文本；同时可在文件面板中安全地编辑文本文件和预览常见文件类型。

## 范围与约束

- 群聊与私聊都支持本功能，且都仅限其当前会话绑定的本地工作区。
- 云端工作区、未绑定工作区或没有权限的会话不提供读取、编辑、预览、拖拽引用或保存能力，并显示现有不可用状态。
- 文件路径始终经过服务端的本地工作区、会话归属、所有权、规范化、越界和符号链接逃逸校验；前端不得直接访问本机绝对路径。
- 文件拖入不复制文件：发送消息时引用已有工作区相对路径，并持久化路径、名称、MIME 类型和大小。
- 每条消息最多允许现有附件接口规定的数量；已加入的同一路径去重。
- 不将文件夹作为消息附件。文件夹拖入只向聊天正文插入规范化相对路径，优先插入到当前光标位置；输入框没有焦点时追加到正文末尾。
- 首版支持 UTF-8 文本编辑、图片预览、PDF 预览、HTML 预览和其他文件下载；Office 文档仅下载，不在应用内转换或渲染。

## 交互设计

### 文件列表拖放到聊天框

文件列表的文件行与目录行均为原生拖放源，并在 `dataTransfer` 中携带受控的工作区项目数据：相对路径、项目类型和显示名称。文件行同时维持键盘可访问的选择和现有菜单操作。

聊天 Composer 是拖放目标：拖入受支持的工作区项目时展示高亮边框与说明，放下后按项目类型处理。

- 文件：加入 Composer 的待发送附件列表。列表显示名称、类型/大小和移除操作；重复项不重复加入。
- 文件夹：将相对路径插入 Composer 文本。它不出现在附件列表，也不随消息附件持久化。
- 无效或不属于当前会话工作区的数据：忽略，并通过现有错误提示反馈。

用户仍可通过现有文件选择/上传流程添加上传附件；拖放工作区文件与上传附件共用同一个待发送附件模型和发送校验。

### 文件详情面板

选中文件会打开文件详情面板，标题显示路径和文件大小。根据服务端确认的 MIME 类型与可读文本标识选择渲染器：

| 类型 | 行为 |
| --- | --- |
| UTF-8 文本、代码、JSON、Markdown、YAML、XML、日志 | 显示等宽编辑器，可编辑和保存。 |
| PNG、JPEG、GIF、WebP、SVG | 自适应尺寸图片预览，可打开原图。 |
| HTML/HTM | 使用独立 `iframe` 加载内容，启用 `sandbox`，不允许脚本执行、同源访问、表单提交或顶层导航。 |
| PDF | 使用浏览器内置 PDF 查看器加载受鉴权的文件流。 |
| 其余二进制/Office 文档 | 展示文件名、MIME 类型、大小与下载操作。 |

文本预览保持服务端的最大长度限制。超过限制的文本在编辑前明确显示已截断，禁止保存，以免用不完整内容覆盖原文件。

### 文本编辑与冲突

打开可编辑文本时，服务端返回内容、`version` 标识、是否截断和文件元数据。`version` 是内容的稳定摘要，而不是浏览器本地时间。

保存请求携带相对路径、完整文本和打开时的 `version`。服务端在写入前重新安全解析路径并比较当前文件版本：

- 版本一致：以原子写入方式更新文件，返回新的版本和元数据；前端清除脏状态并刷新列表/预览缓存。
- 版本不一致：返回冲突，不写入；前端保留用户未保存的编辑内容，显示“文件已在磁盘上变化”，并提供刷新按钮。刷新前要求用户确认会丢弃本地未保存编辑。
- 文件已删除、改为目录、不可读、不是 UTF-8、超过可编辑大小或成为符号链接逃逸：拒绝保存并保留前端文本，显示可操作错误。

## 架构与数据流

### 前端

- 将工作区项目拖放编码/解析收敛为小型纯函数，避免依赖不可信的 `DataTransfer` 文本。
- 扩展 Composer 的输入模型，使其能追加工作区附件路径并精确插入目录路径文本，同时保留上传队列的状态和现有消息发送行为。
- 为文件面板拆分类型化预览组件：文本编辑器、图片预览、HTML 沙箱预览、PDF 预览和通用文件信息卡。
- 为群聊和私聊提供统一的“当前会话工作区文件上下文”接口；页面层只传递会话 ID、工作区 ID 与附件/正文更新回调。
- 所有获取二进制内容的请求复用认证头并释放临时 Object URL，避免令牌泄露到 URL 或内存泄漏。

### 后端

- 将现有群组工作区文件的安全路径解析与文件元数据逻辑抽取为可供群聊、私聊共享的服务层。
- 对已绑定本地工作区提供受鉴权的读取流接口，响应正确的 `Content-Type` 与下载/内联语义；HTML、PDF、图片由该接口提供内容。
- 新增文本读取详情与条件保存接口。两者复用统一的版本摘要、文本大小上限、UTF-8 校验和原子文件写入。
- 将消息附件验证扩展到群聊、私聊各自绑定的工作区，但继续校验请求方所有权、会话归属、常规文件、唯一性及现有数量限制。

## 错误处理与安全

- 不信任浏览器传入的路径、拖放类型、文件名、MIME 类型或版本号；服务端以实际文件状态为准。
- 预览和编辑 API 不接受目录、绝对路径、父目录片段、UNC 路径或越界符号链接。
- HTML 预览以 Blob URL 或受控内容 URL 载入隔离 iframe，不授予 `allow-scripts`、`allow-same-origin`、`allow-forms`、`allow-popups` 或顶层导航权限。
- PDF 和图片加载失败时显示文件信息与下载，不让错误破坏文件列表。
- 所有保存、预览、下载、拖放错误均本地化为英文和简体中文，并使用现有 toast/面板错误样式。

## 验收标准

1. 群聊和私聊均可将文件列表中的文件拖到 Composer，显示待发送附件，发送后消息含同一路径对应的持久化附件元数据。
2. 群聊和私聊均可将文件夹拖到 Composer，路径插入正文且不形成附件。
3. 重复拖入不会重复添加文件；移除附件不影响磁盘文件；无本地工作区时不产生附件或路径引用。
4. 可编辑 UTF-8 文本可保存，保存后重新打开显示新内容；保存不会截断或破坏文本。
5. 打开后文件被外部修改时，保存收到冲突并且磁盘内容不被覆盖；用户可以明确刷新后放弃本地编辑。
6. 图片、PDF、HTML 分别在对应安全预览中可见；HTML 无脚本与同源权限；未知和 Office 文件显示下载入口。
7. 所有读取、保存、预览、下载和消息附件接口拒绝跨用户、跨会话、云端、无工作区、路径越界及符号链接逃逸访问。
8. 前端类型检查、lint、相关前端测试、后端工作区与消息附件测试，以及生产构建通过。

## 非目标

- 在应用内编辑二进制、图片、PDF 或 Office 文档。
- Office 文档转换、OCR、协同编辑、版本历史或自动合并。
- 把文件夹作为消息附件或递归压缩文件夹。
- 绕过本地工作区安全边界直接访问桌面任意路径。
