# 私聊工作区能力补齐与拖拽修复设计

## 背景

`feat/workspace-file-references-preview` 已为群聊和私聊提供统一的工作区文件读取与预览，但私聊面板被限制为只有 Files 标签，文件重命名和删除也仅在群聊启用。同时，右侧文件列表使用自定义 MIME 传递结构化拖拽数据；部分桌面 WebView 在 `dragover` 或 `drop` 阶段不暴露该 MIME，导致输入框没有接受拖放。

## 目标

- 私聊右侧工作区与群聊一致显示 Files 和 Git 标签。
- 私聊文件和目录支持重命名、删除。
- 从右侧文件列表拖动文件到 Composer 时，将文件作为现有工作区附件加入草稿。
- 从右侧文件列表拖动目录到 Composer 时，在当前选区插入目录相对路径；输入框无焦点时追加到末尾。
- 保留现有权限、路径安全、附件数量和服务端元数据校验。

## 非目标

- 不新增私聊外部文件上传。
- 不递归附加目录内容。
- 不引入新的拖拽库、状态管理层或按 workspace ID 的全新 API。
- 不改变群聊现有文件、Git、预览和外部上传行为。

## 方案

### 私聊工作区面板

将现有群聊工作区面板收敛为可接收 `ConversationScope` 的共享面板。Files 标签把实际 scope 和 conversation ID 传给 `ConversationWorkspacePanel`，确保私聊仍通过私聊读取与预览接口访问文件。Git 标签继续复用 `WorkspaceGitTab`；现有 Git 后端入口已按已登录用户、活动会话和本地工作区解析根目录，可接受私聊会话 ID。

`ConversationChatView` 不再按 scope 选择两个不同的右侧壳组件，而是始终渲染同一个 Files/Git 面板并传入当前 scope。

### 重命名和删除

`WorkspaceFilesTab` 不再用 `scope === 'groups'` 禁用重命名和删除。它把当前 conversation ID 交给现有重命名和删除 mutation；后端现有 `/groups/:id/workspace-files` 兼容普通群聊和私聊会话，并继续执行所有权、活动状态、本地工作区和路径边界检查。

成功后同时失效当前 scope 的文件查询和该会话的 Git 查询。失败继续使用现有本地化错误和确认对话框。删除目录保持非递归语义，非空目录由服务端拒绝。

### 文件和目录拖拽

拖拽源继续同时写入：

- `application/x-ag-swarmer-workspace-item+json`：包含版本、相对路径、名称和 `file | directory` 类型。
- `text/plain`：包含换行分隔的相对路径，作为桌面 WebView 后备格式。

Composer 的 `dragenter` 和 `dragover` 将 `text/plain` 视为可候选拖拽类型，以确保浏览器允许触发 `drop`。`drop` 时优先读取结构化格式；如果结构化格式不可用，则读取现有 `text/plain` 路径列表并通过当前会话文件接口逐项确认类型：

- 服务端确认是文件：读取元数据后加入工作区附件。
- 服务端确认是目录：在 textarea 当前选区插入相对路径；无焦点时追加。
- 路径不存在、越界、无工作区或不可读：不加入草稿并显示现有错误提示。

任何拖拽都不会直接创建、移动、复制或删除磁盘内容。

## 数据流

1. 用户从 `WorkspaceFilesTab` 开始拖动一项或多项。
2. 拖拽源写入结构化 MIME 和纯文本路径。
3. Composer 卡片在 `dragover` 调用 `preventDefault()` 并显示高亮。
4. Composer 在 `drop` 优先解码结构化数据，否则读取纯文本路径。
5. Composer 使用当前 `scope + conversationId` 向服务端确认路径和类型。
6. 文件成为待发送附件；目录路径写入输入框。

私聊文件操作沿用：

1. `WorkspaceFilesTab` 提交当前会话 ID 和相对路径。
2. 服务端验证登录用户、会话所有权、本地工作区和规范化后的目标路径。
3. 完成重命名或删除。
4. 前端失效私聊文件缓存与该会话 Git 状态。

## 错误处理

- 没有本地工作区时，面板和 Composer 使用现有“无本地工作区”提示。
- 结构化和纯文本拖拽数据都为空时，显示现有“不支持的拖拽内容”提示。
- 文件元数据验证失败时，不添加伪造附件。
- 目录验证失败时，不修改输入框。
- 重命名冲突、非空目录删除和 Git 错误由现有服务端错误映射到本地化提示。
- 不放宽现有附件数量限制、路径规范化或符号链接防护。

## 测试

前端最小回归覆盖：

- 私聊渲染 Files/Git 两个标签并把 `direct-chats` scope 传给文件面板。
- 私聊文件行显示并调用重命名、删除操作。
- 私聊文件操作成功后失效私聊文件缓存和 Git 状态。
- 只有 `text/plain`、没有自定义 MIME 的拖拽仍能触发 drop。
- 纯文本后备中的文件经服务端确认后成为附件。
- 纯文本后备中的目录在当前选区插入相对路径，无焦点时追加。
- 无效路径和无工作区不改变附件或输入文本。

后端使用现有工作区文件与 Git 测试验证私聊 ID 的所有权和路径边界；若现有覆盖不能证明重命名、删除和 Git 状态支持私聊，则各补一个最小端到端用例。

## 验收标准

- 私聊右侧能切换 Files/Git。
- 私聊文件和空目录可重命名、删除，失败时有明确提示。
- 群聊和私聊都能把右侧文件拖入 Composer 作为附件。
- 群聊和私聊都能把右侧目录拖入 Composer，并在光标位置插入相对路径。
- 桌面 WebView 只暴露 `text/plain` 时拖拽仍可用。
- 相关前后端测试、类型检查和格式检查通过。
