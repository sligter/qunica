# Agent Note: 为什么把群笔记决策记录方法内置到 Qunica

Status: implemented

## Problem

仓库规范只约束开发 Agent，用户在 Qunica 新建群笔记仍得到空白正文，其他群的 Agent 也收不到维护规则。

## Decision

新建界面内置四段模板、状态及类别选择，空内容创建接口提供默认模板，群 Agent 和内置 Assistant 收到统一写作规则。元数据保存在 Markdown 头部，旧笔记原文兼容，宿主维护 UUID 路径和纯列表索引；写作规则只经系统提示下发一次，索引不重复携带。

## Alternatives considered

不做 / 复用现有方案：只改 AGENTS.md 成本最低，但不能覆盖产品内其他群。新增数据库字段可方便筛选，但 Agent 直接编辑文件会产生双份事实；正文元数据更契合现有文件为准的读取方式。强制校验所有正文能统一格式，但会阻断旧笔记及代码决策链接。

## Consequences

收益是用户及 Agent 共用可发现的写作入口；代价是模板与提示需要保持一致，语义质量仍需作者判断。出现大量格式漂移或需要跨笔记检索状态时必须重访校验及索引方案。
